# Кликабельные скрипты, выбор аккаунтов и переносимость

Дата: 2026-08-02. Статус: согласовано, готово к плану реализации.
Предыдущая спека: `2026-08-01-claude-code-app-support-design.md`.

## Задача

Проект работает, но пригоден пока в основном автору. Нужно: запускать типовые операции кликом, а не командой; выбирать в настройках, какие аккаунты открывать и между какими шарить чаты; довести проект до состояния, когда его можно отдать другому человеку.

### Что выяснилось до проектирования

**Шаринг чатов уже работает, синхронизацию строить не нужно.** Проверено на живой машине: после ночи работы все четыре листа `<accountUuid>/<orgUuid>` остались симлинками на пул, пул активно пишется обоими запущенными экземплярами приложения, списки чатов в обоих окнах совпадают. Индекс чатов — физически один каталог, транскрипты и так общие в `~/.claude/projects`. Изначально запрошенный «скрипт, который подливает изменения чата в другой аккаунт» дублировал бы то, что делает пул, поэтому вместо него — кнопка «привести шаринг в порядок».

**Переносимость в лучшем состоянии, чем ожидалось.** В коде нет ни абсолютных путей, ни личных данных (проверено grep по репозиторию; `/Users/someone` встречается только в тестовых фикстурах). Платформенные допущения закрыты проверками `sys.platform != "darwin"` и переменными `CLAUDE_LOGIN_APP_PATH` / `CLAUDE_LOGIN_APP_SUPPORT`. Остаётся оснастка вокруг: исполняемый бит, инструкция первого запуска, онбординг-команда.

## Принятые решения

1. **Скрипты — тонкие обёртки над подкомандами.** Вся логика остаётся в Python, где её покрывают тесты. Отклонено: логика в bash (вторая непроверяемая реализация тех же правил) и единый скрипт с меню (перестаёт быть кнопкой).
2. **Открывать по умолчанию все зарегистрированные аккаунты**, с возможностью сузить список в настройках.
3. **Шаринг — галочка у аккаунта, пул один.** Отклонено: именованные группы (несколько пулов, перенос между ними — сложность без запроса) и пара «откуда-куда» (не масштабируется и не ложится на общий пул).
4. **Глобальный переключатель `Share chats & projects` убирается**, его роль берёт список аккаунтов: снять все галочки и есть «выключено». Два контрола на одно и то же — лишний.
5. **Из дополнительных идей взяты `setup` и скрипт диагностики.** Запуск аккаунта с наибольшим запасом лимита и компактный вывод лимитов отклонены пользователем.

## Архитектура

### Скрипты

Каталог `scripts/` в корне репозитория. Расширение `.command` — по двойному клику Finder открывает файл в Терминале.

| файл | подкоманда |
| --- | --- |
| `setup.command` | `claude-login setup` |
| `open-accounts.command` | `claude-login app open` |
| `sync-all.command` | `claude-login sync-all` |
| `doctor.command` | `claude-login doctor` |

Кнопок для «привести в порядок» сделана одна, а не две. Изначально предполагались отдельные — для чатов и для скиллов с MCP, — но это разные механизмы одной цели, и две кнопки заставляют выбирать, какую нажать. `sync-all` делает всё и идемпотентен; отдельные подкоманды остаются в командной строке для тех, кому нужна точечная операция.

Общая рамка у всех одинаковая и не содержит логики:

```sh
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "${BASH_SOURCE[0]}")/.."
./bin/claude-login <команда>
printf '\nНажмите Enter, чтобы закрыть окно… '
read -r _
```

`cd` от собственного пути — чтобы скрипт работал из любого места, куда склонирован или распакован проект. Пауза в конце — потому что Терминал закрывает окно по завершении, а вывод `doctor` нужно успеть прочитать.

### Новые подкоманды

**`claude-login app open [имена…]`** — открывает приложение под несколькими аккаунтами. Без аргументов берёт `appOpenAccounts` (а если ключа нет — все зарегистрированные профили). Уже открытый каталог данных пропускается с заметкой, определяется существующим `claude_app.is_in_use`. Между запусками пауза `LAUNCH_STAGGER = 1.5` с: четыре Electron-процесса, стартующие в одну секунду, дерутся за CPU и за первый доступ к общим бинарям.

**`claude-login sync-all`** — одна операция «сделать общее общим», из шагов, которые уже есть:

1. `relink` — симлинки CLI: скиллы, плагины, агенты, команды, хуки, `settings.json`, `CLAUDE.md`;
2. `sync --gather` — MCP-серверы и доверенные папки;
3. `app relink` — общее приложения: расширения, их настройки, `claude_desktop_config.json`;
4. `app link` и `app adopt` — пул чатов.

Каждый шаг печатает свою строку итога; ошибка одного шага не отменяет остальные, а суммируется в конце. Флаг `--dry-run` пробрасывается в шаги, которые его понимают.

**Двусторонний перенос MCP: `sync --gather`.** Сейчас `sync_config` копирует только в одну сторону — из машинного `~/.claude.json` в профили. Сервер, установленный внутри профиля, до остальных не доезжает. Добавляется предварительный шаг: собрать `mcpServers` из всех профилей в машинный конфиг, печатая, что именно добавляется, и только потом раздать всем. Правило разрешения — **объединение по имени сервера, машинный конфиг главнее при совпадении имени**. Молча воскрешать удалённое нельзя, поэтому сбор только добавляет отсутствующее и никогда не переписывает существующее; удаление сервера везде остаётся ручной операцией через машинный конфиг.

**Чего перенести нельзя.** Удалённые коннекторы (Google Drive и прочие из claude.ai) привязаны к аккаунту и организации на стороне Anthropic: в файлах сессий видны только их uuid и список инструментов, а сама авторизация живёт на сервере. Локально их не скопировать — подключаются в каждом аккаунте отдельно. Это ограничение продукта, а не утилиты, и README говорит об этом прямо, потому что иначе выглядит как пропажа.

**`claude-login setup`** — идемпотентный онбординг, безопасный к повторным запускам:

1. проверяет `claude` и бандл приложения, называет отсутствующее и что с этим делать;
2. печатает уже зарегистрированные аккаунты;
3. предлагает добавить ещё — цикл `cmd_add`, пока пользователь не откажется;
4. спрашивает цель запуска по умолчанию (CLI / App / ask);
5. связывает пул и втягивает существующие чаты (`app link`, затем `app adopt`);
6. печатает содержимое `scripts/` и назначение каждого файла.

Без терминала (не-TTY) команда ничего не спрашивает: печатает состояние и выходит с кодом 0. Это делает её пригодной для проверки в тестах и в CI, если тот когда-нибудь появится.

### Модель данных

Два новых ключа реестра, с одинаковым правилом: **ключа нет — значит все аккаунты; ключ есть — ровно перечисленные**. Свежая установка ведёт себя предсказуемо, а после первого захода в экран настроек список становится явным.

| ключ | смысл |
| --- | --- |
| `appOpenAccounts` | кого открывает `app open` |
| `appSharedAccounts` | кто участвует в общем пуле чатов |

`appSessionsShared` удаляется. Совместимость: при чтении реестра `appSessionsShared: false` превращается в `appSharedAccounts: []`, значение `true` игнорируется (эквивалентно отсутствию ключа). Миграция выполняется в `Vault.load` и ничего не переписывает на диске до ближайшей записи.

**Шаринг — свойство аккаунта, применяемое к листу.** Каждый лист каталога сессий называется `<accountUuid>/<orgUuid>`, поэтому решение принимается по `accountUuid` листа, а не по каталогу целиком. Это важно для машинного каталога приложения: в нём лежат листы разных аккаунтов, и аккаунт без галочки должен остаться приватным даже там. `Vault.wire_session_pool` получает параметр `sharing: Optional[set[str]]` — множество `accountUuid`, которым разрешён пул; `None` означает «всем».

Снятие галочки обратимо: аккаунт отвязывается от пула и получает назад собственную копию чатов (`unwire_session_pool`, уже реализован и покрыт тестом). Возврат галочки связывает обратно (`link_session_pool` + `wire_session_pool`).

### Настройки

Подэкран `Settings — Claude Code App` получает две строки, каждая открывает экран со списком аккаунтов и галочками:

```
Settings — Claude Code App

           SETTING                     VALUE
❯ Per-account app profile   on
  Accounts to open          2 of 3          edit
  Accounts sharing chats    2 of 3          edit
  Shared entries            8 entries       edit
  Launch env                0 variables     edit
  App path                  /Applications/Claude.app
```

Экран-список строится тем же приёмом, что экран флагов: `picker.pick` с `on_select`, который переключает галочку и возвращает `True`, чтобы список перерисовался, не выходя из сырого режима терминала. Строка — `[x] email · плашка состояния`.

### Пригодность к публикации

Проект должен уходить на GitHub без личных данных автора, и это должно оставаться верным дальше, а не только в момент проверки.

Аудит на 2026-08-02: личных данных в репозитории **нет**. Все почты — плейсхолдеры (`work@example.com`, `me@home.com`, `one@example.com`); единственный настоящий UUID в коде — `9d1c250a-…`, публичный `client_id` OAuth-клиента Claude Code, одинаковый у всех и уже помеченный в документации как не-секрет; путей вида `/Users/<имя>` нет, кроме тестовых фикстур `/Users/someone`. Всё личное живёт в `~/.claude-accounts` и в каталогах приложения — за пределами репозитория, так было заложено изначально.

Что добавляется:

- **Тест-сторож `TestNoPrivateData`.** Проходит по файлам репозитория и падает, если находит почту вне списка плейсхолдерных доменов (`example.com`, `x.io`, `corp.com`, `home.com`, `b.com`), UUID вне белого списка (публичный `client_id` и тестовые фикстуры) или абсолютный путь в `/Users/`, кроме `/Users/someone`. Пишется один раз, ловит вставленный в спешке вывод `list --json` или скриншот-лог с почтой. Для публичного репозитория это дешевле любой ручной вычитки.
- **Удаляется `.DS_Store`** из каталога проекта: он уже в `.gitignore`, но сам файл лежит и уедет в первый коммит, если добавлять через `git add -f` или архивом.
- **Раздел про приватность в README.** Ключевое, что должен понять новый пользователь: **никаких кредов в проект вставлять не нужно**. Логинит настоящий `claude auth login` и само приложение, токены хранят они же — в Keychain и в своих каталогах. Утилита только подставляет им другой каталог. Формулировка «вставьте свои креды» тут неприменима, и это стоит сказать прямо, потому что от утилиты переключения аккаунтов ждут обратного.

### Переносимость

- **`install.sh` ставит `chmod +x` на `scripts/*.command`.** Проект не под git; друг получит zip, где бит исполняемости теряется, и двойной клик молча не сработает.
- **Раздел «Первый запуск» в README** — путь от нуля до двух открытых окон, с оговоркой про Gatekeeper: скачанный архив помечается карантином, поэтому первый запуск `.command` делается через правый клик → «Открыть».
- **Скрипты не предполагают, куда распакован проект.**

## Обработка ошибок

| ситуация | поведение |
| --- | --- |
| в `appOpenAccounts` имя удалённого профиля | пропускается с заметкой, остальные открываются; список чистится при следующей записи |
| шаг `sync-all` упал | остальные шаги выполняются, в итоге печатается, какой шаг не прошёл, код возврата ненулевой |
| `app open` без единого доступного аккаунта | сообщение «нечего открывать» и код 0, а не ошибка |
| приложение не установлено | `ClaudeAppError` из `find_app`, `setup` называет это отдельным пунктом и продолжает про CLI |
| `setup` без терминала | печатает состояние, ничего не спрашивает, код 0 |
| снятие галочки, пока профиль открыт в приложении | отвязка не выполняется для этого каталога, печатается, какое окно закрыть |

## Тесты

Новые классы в `tests/test_claude_login.py`, наследники `_AppBase`:

- `TestAccountSelection` — отсутствие ключа означает «все»; пустой список означает «никто»; `appSessionsShared: false` мигрирует в пустой `appSharedAccounts`; имя удалённого профиля не ломает выборку.
- `TestPerAccountSharing` — лист аккаунта без галочки не уходит в пул даже в машинном каталоге; лист с галочкой уходит; снятие галочки возвращает чаты в собственный каталог.
- `TestAppOpen` — открывает всех при отсутствии ключа; только перечисленных при наличии; пропускает уже открытый каталог; аргументы командной строки перебивают настройку.
- `TestSetup` — не задаёт вопросов без терминала и завершается кодом 0; повторный запуск ничего не ломает.
- `TestScripts` — каждый файл в `scripts/` начинается с шебанга, содержит `bin/claude-login` и имеет бит исполняемости. Дешёвая защита от гниения обёрток.
- `TestNoPrivateData` — в репозитории нет почт вне плейсхолдерных доменов, UUID вне белого списка и путей `/Users/…`, кроме тестовых. Сторож для публикации на GitHub.
- `TestGatherMcp` — сервер, добавленный только в профиле, попадает в машинный конфиг и оттуда во второй профиль; одноимённый сервер в машинном конфиге не переписывается; удалённый из машинного конфига не воскресает из профиля при обычном `sync`.
- `TestSyncAll` — выполняет все шаги, продолжает после ошибки одного и сообщает о ней в итоге; `--dry-run` ничего не меняет.

## Что осознанно не делаем

- Не строим копирующую синхронизацию чатов: пул уже даёт общий список, вторая механика на то же самое только разошлась бы с первой.
- Не делаем именованные группы шаринга.
- Не добавляем запуск по остатку лимита и компактный вывод лимитов — отклонены пользователем.
- Не трогаем поведение цели CLI.
